## ソースと組み立て
- `src/core.js`：分析の本体（読み取り・集計・コメント生成）。Nodeからも `require` できる
- `src/template.html`：画面。`/*CORE*/` の位置に core.js が入る
- `gas/`：Apps Script ウェブアプリ（`Code.gs`・`appsscript.json`・`index.html`（build.pyが作る）・`SETUP.md`）
  - 画面は同じ template.html。`google.script.run` があるときだけ「共有ドライブから読み込む」モードになる（`startDrive`／`loadDrive`）
  - ドライブ：ROOT_FOLDER_ID（スクリプトプロパティ）の下に「エリア」フォルダと「共通」フォルダ。「アクセスしているユーザーとして実行」で権限はドライブの共有に任せる
  - 標準比の店舗設定はスクリプトプロパティ（std_店舗コード）に保存し全員で共有。ブラウザ版は localStorage
  - ウェブアプリモードではブラウザ（IndexedDB）に保存しない。毎回ドライブから読む
  - ローカルでの確認は google.script.run をまねたモックで行った（Playwright の exposeFunction）。本番のデプロイは利用者が SETUP.md の手順で行う
- `src/build.py`：HTMLを作る。1ファイル版は `npm i xlsx@0.18.5` の `dist/xlsx.full.min.js` のパスを引数で渡す
- 保存データの形式を変えたら template.html の `DATA_VERSION` を上げる（元ファイルから自動で読み直す）
- 保存は月ごと：STORE = { months: { 月の通し番号(年×12＋月-1): { cur, prev, menu, pMenu, pays, pPays, invFiles, tc, ws, hourly } }, wage, stdBook, stdLane, active }。表示中の月は viewOf(STORE, k) で以前と同じ平らな形（S）にして使う。以前の1か月だけの形は toStore で変換
  - 振り分け（handleFiles）：売上集計表の月を当年の月とし、12か月前の売上集計表・メニュー別・値引詳細はその月の前年分。タイムカード・勤務スケジュールは売上集計表のある月だけ保存（ほかの月は履歴のみ）。新しい4か月分まで
  - 2026/11/10 の不具合：11月（当日書き出し）と10月のファイルを一緒に入れると、当年＝最新月（11月）になり10月のABC・前年・原価管理表が「月が合わない」で外れていた。月ごとの保存にして解消

## 社内の定義（確認済み）
- 売上＝純売上高（税抜・値引後）。予算は「売上月次予算」（日別）
- 原価分析の率はすべて **値引前売上高（純売上高＋税抜値引）** が分母（原価管理表と同じ基準）
  - 理論原価率＝売上集計表の「原価」÷値引前売上高（メニュー別の予定原価×販売数の合計と一致）
  - 原価率理論差＝値引前原価率−理論原価率。ロス込原価率理論差＝原価率理論差−値引前ロス率
- ロス＝売上集計表の「廃棄額」（元データのCSVではDJ列）
- 直営／FC は「FC区分」列（「直営…」「FC…」）。営業部は「営業部」列
- 人時売上は使わない（社内に独自指標あり。内容は未確認）

## 利用者の判断（2026/11/10）
- 時間帯の予算按分・予算設計は当てにならない → 時間帯・曜日区分×時間帯は前年比で見る（grid の yoyDay＝1日あたり前年比、dayDiff＝1日あたり前年差）。曜日区分（平日・休前日…）は日別の予算があるので予算比のまま
